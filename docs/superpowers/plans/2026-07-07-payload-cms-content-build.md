# Payload CMS Content Build — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a self-hosted Payload CMS to the existing Next.js site so Kind Sisters staff can create, edit, and delete Blogs, Gallery photos, Events, and Testimonials themselves, with images optimised on upload.

**Architecture:** Payload 3 installs *inside* the existing Next.js App Router app: a `(payload)` route group serves the `/admin` editing UI and auto-generated REST/GraphQL, backed by a SQLite database on disk. The public frontend keeps its current design but reads Blog/Events/Gallery/Testimonials from Payload's Local API (same process, no network hop) instead of hardcoded data. Media collections auto-resize images via `sharp`.

**Tech Stack:** Next.js 16 (App Router) · Payload CMS 3 · `@payloadcms/db-sqlite` · `@payloadcms/richtext-lexical` · `sharp` · TypeScript · Tailwind CSS 4.

**Scope note:** This plan is the software build (Phases 1 of the spec). The Australian hosting provision, DNS cutover, backups, and VentraIP cancellation are a separate operations runbook (`docs/superpowers/runbooks/` — to be written) because they are infra ops, not TDD software. Cancelling VentraIP is gated on Jody's explicit go-ahead.

## Global Constraints

- Framework: **Next.js 16.2.6**, App Router only. Payload is a **fully ESM** project — the app must run as ESM (`"type": "module"` or `.mjs` config where required).
- CMS: **Payload 3**. DB: **SQLite** via `@payloadcms/db-sqlite`. Rich text: **lexical** (`@payloadcms/richtext-lexical`).
- Editable collections (v1): **Blog, Events, Gallery, Testimonials** — full **create / edit / delete**. Every one has **drafts + version history** (`versions: { drafts: true }`) and **soft-delete/trash** (`trash: true`). Marketing pages (Home/About/Programs/Contact) stay developer-maintained; do NOT convert them.
- Roles: **admin** and **editor**. Editors do full CRUD on the four content collections; only admins manage Users.
- Images: uploaded through the admin, **auto-resized** on upload (`imageSizes`); originals + sizes stored under `public/media` and served statically. Alt text is a required field on every image.
- Auth secret + DB path come from env: `PAYLOAD_SECRET`, `DATABASE_URL` (e.g. `file:./kindsisters.db`). Never commit secrets or the `.db` file (add to `.gitignore`).
- Data residency: nothing in this build calls a US SaaS. (Deploy target is Australian; see runbook.)
- Authorship: any generated author/attribution field uses **"GBIT Automation"** or the client's name — never an AI/model name. No AI-attribution lines in code, commits, or docs.
- Commit after every task. Run `npx tsc --noEmit` and `npm run build` before declaring a task done where the task changes app code.

### Task 8: Seed script — migrate existing gallery + testimonials into the CMS

**Files:**
- Create: `scripts/seed-content.mjs`
- Uses: existing `public/images/gallery/*` and the current testimonials from `src/app/stories/page.tsx`

**Interfaces:**
- Consumes: the Local API `getPayload`, the `gallery` and `testimonials` collections.
- Produces: seeded Gallery items (one per existing optimised photo) and Testimonial records matching the three real ones already on the site.

- [ ] **Step 1: Write the seed script**

```js
// scripts/seed-content.mjs
import { getPayload } from 'payload'
import config from '../payload.config.ts'
import { readdir } from 'fs/promises'
import path from 'path'

const testimonials = [
  { quote: "The response from families has been overwhelmingly positive...", role: 'Primary School Support Worker', date: 'June 2026' },
  { quote: "At our school we have a high number of students who come from a refugee background...", role: 'Senior Multicultural Support Worker', date: 'October 2025' },
  { quote: "I dropped off the bags to some of our most vulnerable families...", role: 'School Support Worker', date: 'March 2026' },
]

const run = async () => {
  const payload = await getPayload({ config })
  // Testimonials
  for (const t of testimonials) {
    await payload.create({ collection: 'testimonials', data: { ...t, _status: 'published' } })
  }
  // Gallery: upload each existing optimised photo as a gallery item
  const dir = path.resolve('public/images/gallery')
  for (const file of await readdir(dir)) {
    if (!/\.(jpe?g|png)$/i.test(file)) continue
    const alt = file.replace(/\.[^.]+$/, '').replace(/[-_]/g, ' ').replace(/^\w/, c => c.toUpperCase())
    await payload.create({
      collection: 'gallery',
      data: { alt, _status: 'published' },
      filePath: path.join(dir, file),
    })
  }
  console.log('Seed complete')
  process.exit(0)
}
run()
```

> Copy the full testimonial text from the current `src/app/stories/page.tsx` when filling the `quote` fields (do not truncate).

- [ ] **Step 2: Run it** — `npx tsx scripts/seed-content.mjs`. Expected: "Seed complete"; `/admin` shows the testimonials and one Gallery item per photo, each with a sensible caption.

- [ ] **Step 3: Commit the script** (not the DB)
